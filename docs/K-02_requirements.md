# K-02 운영 감사 요건 보강

## K-02-1 추천 결과 생성/설명 가능성(Explainability) 요건

### 1) 추천 결과 생성 시점 감사 로그 저장(신규)
- 추천 결과를 생성하는 **매 요청/배치 시점**에 아래 항목을 구조화 로그로 저장해야 한다.
  - 입력 신호값(예: 거리, 진료 가능 시간, 리뷰 평점, 사용자 선호 등)
  - 신호별 가중치(모델/룰 엔진에서 실제 적용된 값)
  - 추천 엔진/모델 버전(모델 버전, 피처 스키마 버전, 룰셋 버전)
  - 생성 시각(UTC), 요청 식별자(request_id), 결과 식별자(recommendation_id)
- 로그는 사후 감사 및 재현 가능한 형태(JSON 등)로 보관하며, 보존 주기는 운영 정책을 따른다.

### 2) 상위 노출 사유 사용자 표시(신규)
- 병원 상세 화면 또는 `i`(정보) 버튼을 통해, 해당 병원이 상위 노출된 이유(Top 요인)를 **사용자 친화 문구**로 제공해야 한다.
- 사용자 문구는 내부 피처명을 직접 노출하지 않고 해석 가능한 표현으로 변환한다.
  - 예: "현재 위치에서 가까워요", "지금 진료 가능성이 높아요", "이용자 만족도가 높은 편이에요"
- 표시되는 Top 요인은 추천 시점의 감사 로그와 정합되어야 한다.

## K-02-2 추천 데이터 플로우/공공 영역 광고 정책 요건

### 3) Sponsored 슬롯의 추천 점수 계산 완전 배제(명시 강화)
- 데이터 플로우 상에서 Sponsored 슬롯은 **유기적 추천 점수 계산 파이프라인으로 절대 유입되지 않아야 한다**.
- 즉, Sponsored 데이터는 별도 광고 슬롯 경로로만 처리하며, 추천 랭킹 모델/룰의 입력, 피처 생성, 점수 산출, 재정렬 단계에서 모두 제외한다.
- 감사 시 이를 검증할 수 있도록 파이프라인 단계별 분기(Organic vs Sponsored)를 문서화한다.

### 4) 공공 영역(지자체 화면) 광고 비노출 기본값 및 예외 승인 절차(신규)
- 공공 영역(지자체 화면)의 기본 정책은 **광고 비노출(default deny)** 로 한다.
- 예외적으로 광고 노출이 필요한 경우 아래 승인 절차를 반드시 거쳐야 한다.
  1. 요청 부서가 목적/기간/노출 범위를 포함한 예외 요청서 등록
  2. 서비스 오너 + 정책/법무 검토 승인
  3. 운영 책임자 최종 승인 후 제한된 기간 동안만 활성화
  4. 종료 시 자동 원복 및 사후 기록 보관
- 예외 승인 이력(승인자, 승인일, 적용 화면, 만료일)은 운영 감사 로그로 관리한다.
